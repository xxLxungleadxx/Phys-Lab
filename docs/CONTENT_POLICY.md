# Phys-Lab コンテンツ公開方針

- 制定日: 2026-09-16
- 対象: HTML 教材、シミュレーション、PDF、画像、外部リンク

## 1. 対象と編集方針

Phys-Lab は、高校物理を学ぶ人と、必要に応じて大学初年級の学習者を対象とする個人運営の公開教材サイトである。特定の学校、クラス、授業だけで通じる前提を置かず、教材単体でも目的と使い方が分かるようにする。

文章は次を満たすようにする。

- 高校生が理解できる日本語を使う。
- 公式だけでなく、物理量の意味、条件、単位、考え方を示す。
- 範囲外または発展的な内容は「発展」と明示する。
- 未完成の教材を完成品のように案内しない。
- 誤りが判明した場合は速やかに修正し、必要なら更新日や訂正内容を示す。

## 2. 標準メタデータ

各教材は、HTML への直接記述または将来のデータファイルで、次の項目を同じ意味で管理する。

| 項目 | 必須 | 値・形式 | 用途 |
| --- | --- | --- | --- |
| `title` | 必須 | 日本語の教材名 | `h1`、カード、ページタイトル |
| `subject` | 必須 | 単元識別子 | 単元分類 |
| `level` | 必須 | レベル識別子。複数可 | 対象表示 |
| `type` | 必須 | 教材形式識別子 | 形式分類 |
| `description` | 必須 | 原則1〜2文 | 一覧と概要 |
| `updated` | 必須 | `YYYY-MM-DD` | 最終内容更新日 |
| `related` | 推奨 | 正規 URL の一覧 | 関連教材 |
| `status` | 必要時 | 公開状態識別子 | 準備中等の管理 |

例:

```yaml
title: 投射運動
subject: mechanics
level:
  - physics-basic
type: simulation
description: 初速度と投射角を変え、軌跡と飛行時間、最大高度、水平到達距離の関係を確認する教材。
updated: 2026-09-16
related:
  - /mechanics/
status: published
```

メタデータを HTML に記述する場合も、画面上では利用者向けの日本語に変換して表示する。

## 3. 分類値

### 3.1 単元 `subject`

| 識別子 | 表示名 |
| --- | --- |
| `mechanics` | 力学 |
| `thermodynamics` | 熱 |
| `waves` | 波 |
| `electromagnetism` | 電磁気 |
| `atomic` | 原子 |
| `general` | 全般・学習方法 |

教材が複数単元にまたがる場合は、主となる単元を1つ定め、他単元からは関連教材として案内する。分類の重複が学習上不可欠な場合のみ複数分類を検討する。

### 3.2 対象レベル `level`

| 識別子 | 表示名 | 判断基準 |
| --- | --- | --- |
| `physics-basic` | 物理基礎 | 物理基礎の履修範囲を中心とする |
| `physics` | 物理 | 「物理」の履修内容を含む |
| `advanced` | 発展 | 高校範囲を超える内容、または発展的扱い |

対象が複数レベルに適する場合は複数表示できる。難易度を星の数だけで表現しない。

### 3.3 教材形式 `type`

| 識別子 | 表示名 | UI 上の行動 |
| --- | --- | --- |
| `note` | PDF ノート | 読む |
| `slide` | 授業用スライド | 見る |
| `simulation` | 動かせる教材 | 動かす |
| `external-link` | 外部リンク | 調べる |

### 3.4 公開状態 `status`

| 識別子 | 意味 |
| --- | --- |
| `published` | 公開し、通常導線に掲載する |
| `revised` | 既存公開物を更新した状態。必要時のみ更新情報に使う |
| `planned` | 計画中。主要な教材カードとしては表示しない |
| `archived` | 更新終了。必要な説明と代替導線を付ける |

## 4. 教材本文の要件

すべての教材で、タイトル、対象レベル、概要、更新日を利用者が確認できるようにする。必要に応じて、前提知識、学習目標、関連教材を加える。

物理内容では次を確認する。

- 記号を初出時に説明している。
- 数値には単位を付けている。
- ベクトル量とスカラー量を混同していない。
- 数式が成立する条件と近似を示している。
- 図、グラフ、本文、計算結果が一致している。
- 初期条件、符号、座標軸、正方向が分かる。
- 表示上の丸めと内部計算を区別している。

物理的正しさと教育的な難易度は、Codex の検証だけで確定せず、人間が最終確認する。

## 5. シミュレーション固有の要件

- 操作によって何を確かめる教材かを冒頭で説明する。
- 入力値の名称、単位、許容範囲を示す。
- 初期値は典型的で、初期表示だけでも意味のある結果にする。
- 0、最小、最大、境界値を含む入力で計算と表示を検証する。
- 結果の主要数値を Canvas 外の HTML にも表示する。
- モデルの前提と、扱わない効果を明示する。
- 再生、一時停止、リセットなどの状態と操作結果を理解できるようにする。
- マウス、タッチ、キーボードで主要操作が可能な標準フォーム要素を優先する。

## 6. PDF 公開方針

公開前に次を確認する。

- 表示題名と PDF 内のタイトルが一致している。
- ファイル名が英数字とハイフンを基本とする説明的な名前である。
- `最終版2.pdf`、`修正版_最終.pdf`、`test.pdf` のような管理用名称ではない。
- Author、Creator、Producer、作成環境、埋め込み添付などのメタデータに公開不要情報がない。
- 氏名、学校名、クラス、内部 URL などが本文・注釈・プロパティにない。
- フォントと図が埋め込まれ、主要端末で崩れず読める。
- ファイル容量が用途に対して過大でない。
- HTML 側に内容、対象レベル、ファイル形式を示す。

既存 PDF の URL やファイル名を変更する場合は、外部リンクへの影響を確認し、旧 URL の互換性を保つ。

## 7. 画像・図・数式

- 自作または利用条件を確認できる素材だけを使用する。
- 意味のある画像には、学習上必要な情報を含む代替テキストを付ける。
- 装飾画像には空の `alt` を使い、読み上げの妨げにしない。
- 図中の色だけで系列、正負、対象レベルを区別しない。
- 数式の画像化は避け、可能な限りテキストまたは適切なマークアップで表す。
- AI 生成画像を使う場合も、物理的誤り、権利、メタデータ、ファイル容量を人間が確認する。

## 8. 外部コンテンツと著作権

- 他サイトの本文や画像をコピーしない。
- 教科書、問題集、授業資料、大学入試問題を許諾なく転載しない。
- 外部教材の紹介は、必要最小限の説明を添えたリンクを基本とする。
- 引用が必要な場合は、必要性、範囲、主従関係、出典表示を確認する。
- 外部リンクには提供元とリンク先の内容が分かる文言を付ける。
- リンク先の内容、対象レベル、安全性、リンク切れを公開時に確認する。

リポジトリ全体のライセンスが決定・明記されるまでは、公開されていることを再利用許可と同一視しない。将来ライセンスを定める場合は、教材、PDF、コード、画像の適用範囲と第三者素材の例外を明記する。

## 9. 個人情報・学校情報・秘密情報

次は公開しない。

- 生徒や関係者の氏名、成績、学籍・クラス情報
- 勤務先・学校を特定する情報
- 学校メールアドレス、内部 URL、Teams / SharePoint URL、校内 IP
- API キー、トークン、パスワード、秘密鍵、環境変数
- ファイルのコメント、履歴、PDF メタデータに残る同種の情報

公開前に本文だけでなく、HTML コメント、スクリプト、ファイル名、メタデータも確認する。秘密情報が一度 Git 履歴へ入った場合は、ファイルを削除するだけでは不十分として、資格情報の失効と履歴対応を検討する。

## 10. 更新と廃止

- `updated` は見た目だけの修正ではなく、教材内容を最後に確認・更新した日とする。
- トップページの更新情報は、利用可能になった教材または重要な改訂を簡潔に示す。
- 日付を更新するだけの変更はしない。
- 教材を廃止する場合は、可能なら旧 URL に理由と代替教材へのリンクを残す。
- 定期的に外部リンクと古い説明を点検する。
